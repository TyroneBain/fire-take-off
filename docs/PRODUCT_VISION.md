# Product vision

Fire Take Off will reproduce Countfire's user-facing takeoff and estimating capabilities with an original implementation. The initial user is a single estimator using a private application on macOS. The eventual target is complete functional parity, including publicly documented collaboration and integrations; an initial local workflow does not remove those obligations.

The core workflow is: create a project, organise drawing sets and disciplines, review high-resolution PDFs, select and count symbols across drawings/floors, inspect and correct results, calibrate and measure, divide quantities into zones, handle overlays/revisions, produce auditable schedules and Excel outputs, then price and export estimates.

Required trades include sprinkler, hydrant, electrical, mechanical and general construction. A trade being requested does not establish that Countfire has a dedicated module for it. Track evidence and unknowns separately. Include notes, coverage visualisation, Smart Select, connected measures and fittings, floorplans, specification comparison, libraries/kits, margins and preliminaries where public evidence supports them.

Success requires reliable workflows on representative authorised construction drawings, durable project recovery, traceable manual corrections, tested numerical accuracy and reproducible acceptance evidence per feature. A plausible interface, a single successful drawing or a marketing assertion is insufficient.

Scope boundaries: Phase 0 establishes memory, research inventory, architecture evaluation and REA verification. No product build begins until its gate passes. No unrelated products or AI designer features. All branding, code and fixture assets must be original or appropriately licensed. Learn from public documentation and authorised normal interaction; do not extract proprietary source or circumvent access controls.

Public research is a baseline dated 2026-10-22, not a claim of exhaustive parity. Phase 1 must resolve unknowns, specify each workflow and freeze a dated reference baseline. Future Countfire changes enter the parity backlog explicitly.
