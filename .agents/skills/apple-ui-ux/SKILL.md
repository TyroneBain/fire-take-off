# Apple-inspired Fire Take Off UI/UX

## Purpose
Use this skill for UI/UX reviews, design proposals and later authorised implementation of the Fire Take Off interface. Do not run it as a substitute for counting/recognition engineering.

## Required references
- Apple Design Resources: https://developer.apple.com/design/resources/
- Apple Human Interface Guidelines: https://developer.apple.com/design/human-interface-guidelines/
- Project design contract: docs/design/APPLE_HIG_AGENT_REFERENCE.md
- Project UI rules: docs/design/APPLE_DESIGN_RULES.md
- Current priorities: docs/PRODUCT_EXECUTION_SOURCE_OF_TRUTH.md

## Retained owner preference (2026-11-06)
Original Apple-inspired dark mode: graphite navigation and tool chrome, a bright readable PDF drawing canvas, restrained amber count markers, clean hierarchy and precise desktop controls. User likes the concept because it is visually distinct from Countfire. Mockups are not production approval.

## Procedure
1. Check current official Apple guidance and any resource licences; record the review date.
2. Map the user's task and state transitions before drawing screens. Prioritise symbol selection, element editing, matching, review and saved corrections.
3. Propose original components and icons; do not copy Apple assets or competitor trade dress without applicable rights.
4. Test 1280x800, 1440x900 and 1920x1080; keyboard, focus, contrast, long labels, zoom, loading and errors.
5. Keep PDF readability, quantities, zones, correction history and Excel exports intact.
6. Remain advisory until the lead explicitly assigns production UI changes; P0 counting accuracy comes first.

## Deliverable
An annotated design proposal with exact official reference links, rationale, states, viewport checks, accessibility notes, licensing notes and no-regression criteria.
